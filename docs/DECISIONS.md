# 夜讀（Night Reading）— 已拍板決策與現況

> 單一真理來源。每拍一個板就更新這份。研究流程與數據見 `research/`，紅線測試見 `research/nightread_guard.py`。

## 定位

漫畫夜讀模式＝**頁面本身**變暗（不是 UI 黑）。業界所有 reader 只做 UI 黑或硬反相；沒有人動過頁面內容——可能首創。
數學結論（實驗確立、別再挑戰）：漫畫的紙白參與構圖（臉的亮部、留白都用紙白畫）⇒「白→暗」的全域函式無解；
只有**分區重繪**（氣泡深底亮字、背景填黑、前景白描邊）拿得到夜讀效果——這是 Yakuyomi 的護城河，濾鏡永遠做不到。

## ★ 人物語意遮罩（2026-09-14 定案）

紅線問題解決：**違規 55 → 6 框，亮區只付 2.9pt**（純幾何路線最好是 37 框且要付 14pt）。

**定案配方**：`cseg ∪ yoloseg` 遮罩、外擴 20px、`CHAR_OVER_BUBBLE=1`（人物優先於氣泡）、
**字貼身暗襯 r=5**（`TEXT_BACKING_R`）。全部已設為程式預設。
機制＝`compose` 最後一步把人物區還原成場景調；**還原只扣氣泡/偽泡、絕不扣 gutter**
（白衣被塗黑正是 gutter 幹的，早期誤扣導致只降 3 框、差點誤判整條路失敗）。

| 遮罩 | 違規 | 亮區 | 效率（框/%面積） |
|---|---|---|---|
| 無 | 55 | 40.3% | — |
| isnet（彩色動畫訓練） | — | — | 0.82（黑白漫畫上無規律，排除） |
| manga109 body bbox | — | — | 0.69（保護 80% 頁面，排除） |
| yoloseg（黑白漫畫像素遮罩） | 24 | 41.5% | 1.66 |
| **cseg（CartoonSegmentation）** | 21 | 41.9% | — |
| cseg ∪ yoloseg | 20 | 42.0% | — |
| ＋人物優先於氣泡 | **6** | 43.2% | — |
| **＋字貼身暗襯 r=5（定案）** | 9 | 43.2% | — |

**字貼身暗襯**：人物優先會把「寫在畫面上的字」的深底一起還原掉，而原作是靠**白描邊**把黑字從
畫面分出來的——lin8 把白描邊壓到 140、畫面也落在 90–140 ⇒ 描邊失效、字埋進畫面（demo01 上兩格
實例，使用者回報）。修法＝人物區還原時留一條貼著筆畫的窄帶不還原，該帶維持「填深＋亮字」。
窄帶處原本就被字本身遮住 ⇒ 不損人物細節。代價＝多 3 框（襯底壓在人物上），亮區不變。

**首選模型＝CartoonSegmentation / AnimeInstanceSegmentation**（RTMDet-Ins + IS-Net）：
**MIT 權重**（比 yoloseg 乾淨——後者要背 Ultralytics AGPL + Manga109-s + MangaSeg 三層義務）、
現成 ONNX 圖內含 NMS（不需 mmdet/mmcv）、238MB fp32 / 60MB int8、CPU 六緒 0.25s/頁。
第三方佐證：CVPR 2025《Advancing Manga Analysis》在 927 張 Manga109 人工標註頁上量到
character body Mask AP **0.923＝全表最高**（注意該模型訓練用過整個 Manga109 ⇒ 分數樂觀）。
兩個實作坑：遮罩輸出是**機率**（門檻 0.5，用 >0 會整頁前景）；輸入 **640 最佳**（訓練解析度；
1024 反而掉到 89.6% 臉覆蓋，別照抄 DBNet 的 1024）。

**SAM 路線實測否決**：文獻上「漫畫框 + 原版 SAM」有 0.79 分，但那是 ViT-H 級；能上手機的蒸餾版
把跨域穩健性一起蒸掉——用我們的 bbox 當提示實測，MobileSAM 臉覆蓋 56%、EfficientViT-SAM 6%。
**trapped-ball**（動畫上色的線稿區域分割，MIT、四個 OpenCV 運算、全頁 8ms）遇網點即崩，
不能當主力，可當「在框內把遮罩收斂到封閉線稿」的收緊器（網點判別器當保險絲）。

**剩餘 6 框**：demo03 三隻手（該頁彩色、模型漏抓）、demo04 長髮、demo03 一張臉、ch34_011 背影白外套。

## 現況（2026-09-14）

- 管線：偵測（DBNet，來自 engine parity）→ 頁型判別 → 白元件分類 → 氣泡遮罩 → 貼紙計畫 → 合成（曲線／留白／貼紙／氣泡／偽泡／人頭一致化）。細節見 `research/nightread.py` 檔頭。
- 守護框：**6/665**（定案配方，見上節）。純幾何時代最好 37 框且要付 14pt 亮區——那條線已結案：
  「臉頰／背景同為紙白」沒有任何局部幾何或灰階特徵可分（深度、面積比、實心度、貼厚墨、貼框、
  肥留白全試過）。**別再靠加門檻／旗標追紅線。**
- 已修：偽泡的厚墨灰暈把粗體字筆畫當墨團 → 字旁挖出灰洞（算灰暈前扣掉文字筆畫遮罩）。
- demo01（出血特寫 + 字壓臉）已由人物遮罩解決：主角臉從全黑變完整保留。

## 下一步

桌面演算法已收斂（守護框 6/665）。剩下的是**上機工程**，依序：
1. **cseg 上 Android**：ONNX 圖內含 NMS、全標準 op ⇒ ORT 直接可跑（不需 mmdet/mmcv）。要決定 fp32
   238MB vs int8 60MB（int8 需把分數門檻降到 0.15，臉覆蓋 98.3%→96.1%）；模型走 GitHub release
   下載＋sha256，同 engine 的 models-v3。**自訓已排除（沒資源）**。
2. **Kotlin 移植**：`nightread/` 目前只有 Cv.kt 的 API 契約（TODO 本體）。研究端的 Python 是規格，
   JVM 測試對 fixture 逐位元比對。
3. **產品整合三階段**：reader 濾鏡（lin8 曲線、ColorMatrix）→ 夜讀重繪 method（吃翻譯素材、走現有
   重繪佇列、palette 與去字法正交）→ cleaned 落地。引擎端已知阻礙：`Renderer.textColors` 對 onArt
   區域硬編黑字白邊。
4. 剩餘 6 框與次級瑕疵（彩頁去色、邊界鋸齒）看真機觀感再決定要不要動。
